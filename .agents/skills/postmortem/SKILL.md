# /postmortem

This skill is designed to analyze the `0:/mission_history.log` file generated by the flight computer during a mission to provide a compact post-flight analysis. 

## Instructions

When the user invokes `/postmortem`, you must perform the following steps:

1. **Read the Log**: Use the `view_file` tool to read the contents of `c:\Program Files (x86)\Steam\steamapps\common\Kerbal Space Program\Ships\Script\mission_history.log`.
2. **Analyze the Data**: The log is a CSV with the format `Time,Stage,Body,Alt,Pe,Ap,Inc,EC_pct`. Review the chronological progression of the mission. Look for:
   - **Nominal Progression**: Did the mission pass through all expected stages (e.g. Booting, Pre-Launch, Ascent, Circularization, Hohmann Transfer, Capture)?
   - **Anomalies**: Did the altitude suddenly drop to 0 unexpectedly? Did the EC% (Electric Charge) drop critically low or hit 0% during a crucial stage?
   - **Orbital Changes**: Did the Apoapsis/Periapsis stabilize as expected during Circularization and Capture?
3. **Summarize for the User**: Provide a concise narrative of the mission's evolution. If the mission failed (e.g., vessel crashed or ran out of power), identify the exact stage and timestamp where the failure occurred or where the anomaly first manifested. Keep token usage low by focusing only on key milestones and anomalies, rather than recounting every single snapshot.

## Using Subagents for Live Monitoring

If the user asks to monitor the mission *live* as it happens, you can use the `invoke_subagent` tool to spawn a `Watcher` subagent. You can instruct the subagent to run a background loop that periodically reads `0:/telemetry.json` or `0:/mission_history.log` and alerts you via `send_message` if critical conditions (like sudden altitude loss or power failure) are detected, while you continue working on code.
